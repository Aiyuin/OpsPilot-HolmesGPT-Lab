# 第三章 面向云原生运维的故障诊断 Agent 实验设计

> 状态：实验设计稿。所有标记为 `待填` 的结果必须由 `experiments/chapter3` 原始数据生成，禁止先写结论后补数据。

## 3.1 研究目标

本章针对云原生系统故障排查中信息源分散、诊断路径依赖专家经验以及大语言模型容易产生无依据结论的问题，研究工具增强型故障诊断 Agent 的有效性、收敛性和容错性。实验不以“服务成功部署”作为有效性证明，而是通过在隔离 Kubernetes 集群中注入可重复故障，要求 Agent 自主查询资源状态、事件与日志，并给出与预设根因一致的诊断结论。

本章回答五个研究问题：工具增强是否提升正确率，不同故障类别下性能是否稳定，推理步数约束如何影响效果和成本，工具故障时能否安全降级，以及整体时延与资源开销是否满足交互式运维需求。

## 3.2 实验对象与实现版本

实验系统以 HolmesGPT 为基础，源码固定为提交 `5e983c1`；推理模型采用阿里云百炼 `qwen-plus`，通过 OpenAI-compatible API 接入 LiteLLM。为避免模型能力识别失败导致输出预算超过百炼限制，设置 `OVERRIDE_MAX_OUTPUT_TOKEN=8192`。运行环境包括本机 Conda Python 3.12、Docker Desktop 和单节点 Kind 集群。远程 2C/2G 服务器只用于 API 部署验证，不承载批量 Kubernetes 实验，以避免资源竞争影响测量结果。

## 3.3 实验场景

实验选取配置缺失、镜像拉取失败、健康检查失败、内存溢出、存储类不匹配和网络策略错误六类常见故障。所有场景均来自 HolmesGPT 官方评测夹具，由脚本创建故障资源并等待可观察状态。每次实验结束后清理相应 namespace 或 manifest，防止跨实验污染。

表 3-1 的根因与证据字段由 fixture manifest 和 setup 条件确定，不由模型回答反推。

## 3.4 对照组与实验变量

设置 Direct-Qwen、HolmesGPT-Tool 与 OpsPilot-Bounded 三组。Direct-Qwen 只接收问题描述，不访问环境；HolmesGPT-Tool 使用原始工具调用循环；OpsPilot-Bounded 对推理步数、终止条件和工具故障传播进行约束。本文方法必须以独立实现和 commit 为依据；在实现完成前，本节不得把配置调整写成算法创新。

推理步数消融设置 3、8、30 三个水平；容错实验分别注入工具超时、权限拒绝和单工具缺失。每个“场景 × 方法/配置”组合重复 10 次。

## 3.5 评价指标与统计方法

主要指标为根因正确率、宏平均正确率、终止率、证据完整率和无依据断言率；次要指标为 P50/P95 时延、LLM 调用次数、工具调用次数、token 消耗、CPU 和内存。

正确率报告 Wilson 95% 置信区间，配对方法比较使用 McNemar 精确检验；时延和 token 使用中位数、IQR 与 Wilcoxon signed-rank 检验；多个推理步数使用 Friedman 检验并进行 Holm 校正。显著性水平设为 0.05，同时报告效应量。

## 3.6 实验结果

先导实验已完成 Direct-Qwen 无工具组 6 个场景各 1 次，命中 2/6；由于样本量不足且无环境证据，该结果仅用于验证实验链路，不纳入正式假设检验。HolmesGPT 工具组已在 `09_crashpod` 与 `80_pvc_storage_class_mismatch` 两个场景正确诊断；`17_oom_kill` 暴露了超过 180 秒仍未收敛的问题，其余场景待后续补测。详见 `PILOT_RESULTS.md`。

## 3.8 有效性威胁

内部效度威胁包括模型随机性、场景启动时间差异、共享集群残留状态和 Judge 偏差。通过固定 commit、重复 10 次、严格 setup、逐次清理和人工复核降低影响。外部效度主要受单节点 Kind、场景数量和单一模型限制；结论不能直接外推到大规模生产集群。构念效度方面，根因正确并不等价于完整 SRE 能力，因此同时测量证据完整性、无依据断言和工具效率。
