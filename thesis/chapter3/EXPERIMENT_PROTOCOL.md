# 第三章实验协议：基于大模型的云原生故障诊断 Agent

## 1. 研究定位

论文暂定题目：**面向云原生运维场景的大语言模型故障诊断 Agent 设计与实现**。

研究对象不是“能否调用大模型”，而是工具增强 Agent 在真实故障状态下能否以有限时延和资源开销得到正确、可追溯、可终止的诊断结果。实验以 HolmesGPT 为工程基础，以阿里百炼 Qwen 为推理模型。

西南大学《硕士专业学位研究生培养工作规定》要求专业硕士掌握专门知识、具有解决实际问题和开展应用性研究的能力，论文选题应具有职业背景和应用价值，论文可以采用应用研究、产品开发、案例分析或方法实证研究等形式。本实验将“真实 Kubernetes 故障注入—Agent 自主取证—根因判定—恢复验证”作为应用研究主线。

官方依据：

- <https://ai.swu.edu.cn/info/1085/2268.htm>
- <https://pgs.swu.edu.cn/info/1072/7781.htm>

最终是否达到毕业和送审条件仍以导师、培养方案、学院分委员会和当年研究生院通知为准；本协议只把第三章实验提升到可审查、可复现的工程实证水平。

## 2. 研究问题

- **RQ1 有效性：** 与不使用环境工具的直接大模型相比，工具增强 Agent 是否显著提高根因诊断正确率？
- **RQ2 泛化性：** Agent 在配置、镜像、健康检查、资源、存储和网络六类故障上的表现是否一致？
- **RQ3 收敛性：** 最大推理步数对正确率、终止率、工具调用数、时延和 token 消耗有何影响？
- **RQ4 容错性：** Kubernetes/MCP 工具超时、拒绝或部分不可用时，系统能否终止并明确说明证据缺口，而不是编造根因？
- **RQ5 工程效率：** 在可接受正确率下，系统 P50/P95 时延、token、内存和失败恢复时间是否满足交互式运维需求？

## 3. 假设

- **H1：** 工具增强 Agent 的总体正确率高于直接大模型基线至少 20 个百分点。
- **H2：** 8 步有界推理与 30 步配置的正确率差异不超过 5 个百分点，但中位 token 和时延更低。
- **H3：** 部分工具故障时，降级完成率不低于 90%，无证据确定性断言率不高于 5%。
- **H4：** 六类场景宏平均正确率不低于 80%，任一类别正确率不低于 60%。

这些阈值在看正式结果前固定，避免根据结果移动标准。若未达到，不得修改阈值宣称通过，而应报告失败并改进系统后以新版本重新实验。

## 4. 自变量与对照组

| 变量 | 水平 | 用途 |
|---|---|---|
| 诊断方式 | Direct-Qwen、HolmesGPT-Tool、OpsPilot-Bounded | 基线与拟议方法比较 |
| 最大推理步数 | 3、8、30 | 收敛消融 |
| 工具状态 | 正常、超时、拒绝、单工具缺失 | 容错实验 |
| 故障类型 | 配置、镜像、探针、OOM、存储、网络 | 泛化实验 |
| 重复次数 | 每个组合 10 次 | 控制 LLM 随机性 |

其中 `OpsPilot-Bounded` 必须对应可审查代码实现；未实现前只能把 HolmesGPT 作为复现基线，不能在论文中声称为本文方法。

## 5. 场景与真实性

场景来自 HolmesGPT 官方评测夹具：

| 场景 | 根因 | 类别 | 主要证据 |
|---|---|---|---|
| `09_crashpod` | 缺失 `DEPLOY_ENV` | 配置 | CrashLoopBackOff、容器日志 |
| `10_image_pull_backoff` | 镜像不存在/不可拉取 | 镜像 | Pod 状态、Event |
| `15_failed_readiness_probe` | readiness probe 失败 | 探针 | Pod condition、probe event |
| `17_oom_kill` | 内存限制导致 OOMKilled | 资源 | lastState、limit、event |
| `80_pvc_storage_class_mismatch` | StorageClass 不存在 | 存储 | PVC Pending、ProvisioningFailed |
| `176_network_policy_blocking_traffic_no_skills` | NetworkPolicy 标签选择错误 | 网络 | 前端超时日志、NetworkPolicy |

每次运行由脚本创建故障并等待可观察证据，运行后删除 namespace/manifest。setup 失败必须单独标记，不能算作模型诊断错误。

## 6. 因变量

### 6.1 主要指标

1. **根因正确率**：结果包含场景预定义的全部关键事实，取 0/1。
2. **宏平均正确率**：先计算每类正确率，再对六类取平均，避免类别数量偏置。
3. **终止率**：在最大步数和 180 秒内返回最终答案的比例。
4. **证据完整率**：根因、资源名、命名空间、直接证据、修复建议五项的覆盖比例。
5. **无依据断言率**：答案出现工具结果无法支持的确定性根因比例。

### 6.2 次要指标

- Agent 总时延、P50、P95。
- LLM 调用次数、工具调用次数。
- prompt/completion/total token。
- 最大常驻内存和容器 CPU。
- 工具故障后的降级完成率与恢复时间。

## 7. 评分与偏差控制

1. 硬性事实优先用确定性断言评分，例如是否出现 `OOMKilled`、指定环境变量或 StorageClass。
2. 语义评分使用独立 Judge Prompt；Judge 模型和版本固定，并抽取不少于 20% 样本人工复核。
3. 两名标注者对证据完整性和无依据断言独立评分，报告 Cohen's kappa；分歧由第三方或导师裁决。
4. 场景顺序随机化；不同方法使用同一故障实例或按相同 manifest 重建。
5. 正式实验前冻结代码 commit、场景列表、阈值和统计方法。

## 8. 统计分析

- 二项正确率：Wilson 95% 置信区间。
- 配对正确率：McNemar 精确检验，并报告百分点差和相对提升。
- 配对连续指标：优先 Wilcoxon signed-rank；同时报告中位数和 IQR。
- P50/P95 时延：按场景分层 bootstrap 10,000 次计算 95% CI。
- 多步数比较：Friedman 检验；显著后做 Holm 校正的两两 Wilcoxon。
- 显著性水平 `α=0.05`，同时报告效应量，不只报告 p 值。

## 9. 样本量

核心实验为 6 场景 × 3 方法 × 10 次 = 180 次 Agent 运行；收敛消融为 6 × 3 步数 × 10 = 180 次；容错实验为 6 × 4 工具状态 × 10 = 240 次。正式运行前先做每场景 1 次先导实验验证夹具和 Qwen 兼容性。

如果费用或配额不足，必须在论文中说明功效限制；不能把单次调用当作稳定性结论。可先完成核心实验，再按优先级补消融和容错。
